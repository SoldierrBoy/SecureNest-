# План перевірки лабораторного проєкту (ручні тести)

## Перевірка збірки

- `dotnet --version` показує SDK 10.x.
- `dotnet restore` завершився з кодом 0.
- `dotnet build` завершився **Build succeeded**.
- `dotnet run --launch-profile SecureAccountsLab6` відкриває https://localhost:7080/.
- У Development консоллю створено адміністратора з випадковим паролем (один раз).
- `/dev/mail` показує тестову пошту тільки з localhost.

## Тести основного функціоналу

| № | Кроки | Очікувано |
|---|---|---|
| T01 | Порожні поля реєстрації | Помилки обов'язкових полів |
| T02 | Пароль `12345678` при правильній CAPTCHA | Пароль відхилено політикою Identity |
| T03 | Сильний пароль + неправильна CAPTCHA | Створення відхилено, CAPTCHA одноразова |
| T04 | Сильний пароль + правильна CAPTCHA | Новий акаунт у БД, `EmailConfirmed=false` |

| T06 | Відкрити лист `ACTIVATION` → перейти | Email підтверджено, вхід можливий |
| T07 | Відкрити той самий activation link удруге | Посилання відхилено |
| T08 | 1–4 рази неправильний пароль | Помилки з'явилися в `/admin/logs` |
| T09 | 5-й неправильний пароль | Identity lockout на 15 хвилин |
| T10 | Admin → розблокувати | Лічильник помилок 0, вхід знову доступний |
| T11 | Admin → вручну блокувати активного користувача | Сесія на наступному запиті анулюється, вхід заборонено |
| T12 | Звичайний користувач відкриває `/admin` | 403 / redirect на AccessDenied |
| T13 | Вимкнене 2FA → ввімкнути з правильним TOTP | Статус `2FA увімкнено` |
| T14 | Повторний вхід з 2FA | З'являється друга форма з кодом |
| T15 | Неправильний TOTP | Вхід заборонено, запис `FAILED_2FA` |
| T16 | Правильний TOTP | Вхід успішний, запис `SUCCESS_2FA` |
| T17 | Вимкнути 2FA з неправильним кодом | Заборонено |
| T18 | Вимкнути 2FA з правильним кодом | Статус вимкнено, старий TOTP ключ відкликано |
| T19 | Google OIDC без ClientId | Кнопка Google неактивна/не показується |
| T20 | Google OIDC з валідними ключами | Вхід через Google та профіль (потрібен зовнішній Google) |
| T21 | `Forgot password` на неіснуючий email | Загальне повідомлення без розкриття існування акаунта |
| T22 | Password reset з чинним токеном | Пароль змінено |
| T23 | Password reset з тим самим токеном повторно | Токен більше не дійсний |
| T24 | Logout | Захищений профіль недоступний до нового входу |
| T25 | Вхід зі шляхом returnUrl=https://evil.example | Відкритий редирект не відбувається |

## Перевірка захисту

- У SQLite (`App_Data/accounts.db`) пароль не зберігається як текст; у `AspNetUsers.PasswordHash` зберігається хеш Identity.
- Захищені POST-форми використовують antiforgery, а тести без токенів мають завершитися 400.
- Cookie авторизації має `HttpOnly`. Для HTTPS — `Secure`, `SameSite=Lax`.
- Заголовки HTTP містять `X-Content-Type-Options: nosniff` і `Content-Security-Policy`.
- Логи містять IP, email, результат і UTC-час, але **не містять паролів або TOTP-секретів**.
- SMTP-пароль, ClientSecret та DB-файли не входять в Git (`.gitignore`).

## Обмеження

Google та реальну SMTP-доставку потрібно перевіряти тільки після введення власних налаштувань. Локальна CAPTCHA — демонстраційний механізм, не заміна промисловому антибот-сервісу.
